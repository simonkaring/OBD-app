# VoltLink Agent Guide

## Layout

VoltLink is a two-project repository. Keep the projects independent: neither
build tooling nor source is shared between them.

- `ios/` — the Swift iOS + CarPlay app, its generated `VoltLink.xcodeproj`, the
  SwiftPM package and tests, `Tools/`, `scratch/`, and the OKF knowledge bundle.
  **Paths in this guide are relative to `ios/` unless noted.**
- `android/` — the Kotlin + Jetpack Compose Android app (own Gradle build,
  `android/app/...`), its own `android/knowledge/` OKF bundle and tests. See
  [`android/README.md`](android/README.md) for commands, architecture and the iOS
  parity matrix. Do not add Android code to `ios/`.

## Project

VoltLink iOS is a native Swift iOS and CarPlay OBD-II diagnostics and live EV
telemetry app. It supports the Mercedes-Benz EQA 250 (2021), Vgate iCar Pro
2S BLE adapter, generic SAE J1979 OBD-II, and a demo/simulation mode.

## Commands

Run these from `ios/` (the directory containing `Package.swift` and
`VoltLink.xcodeproj`):

```bash
cd ios
swift test
xcodebuild -scheme VoltLink -destination 'platform=iOS Simulator,name=iPhone 17'
xcodebuild test -scheme VoltLink -destination 'platform=iOS Simulator,name=iPhone 17' \
  -only-testing:VoltLinkUITests   # demo-mode UI smoke test
python3 scratch/make_xcodeproj.py  # regenerate the generated Xcode project
open VoltLink.xcodeproj
./scratch/repack_ipa.sh   # archive & package build/VoltLink.ipa
swift run VoltLinkCLI okf export   # regenerate the knowledge/ OKF bundle
swift run VoltLinkCLI okf check    # validate conformance and drift
swift format lint --strict --recursive --configuration .swift-format \
  Package.swift App CarPlay Core Data Services UI Widgets Tests UITests Tools
```

Run `swift test` after changing PID decoders, ISO-TP parsing, or SwiftData
models. `Package.swift` builds the macOS-testable `VoltLinkEngine`; the Xcode
project builds the iOS/CarPlay app. The Xcode project is generated by
`scratch/make_xcodeproj.py` (including the shared scheme and the `VoltLinkUITests`
target) — regenerate it after adding files or targets instead of hand-editing
`project.pbxproj`. `scratch/` is not part of the app build. Pass
`--local-signing` to generate a project without the CarPlay Driving Task and App
Group entitlements (free Personal Teams cannot provision them), and export
`VOLTLINK_DEVELOPMENT_TEAM=<TeamID>` to keep a team selection.

Both build products compile in Swift 6 language mode (`swiftLanguageModes: [.v6]`
and `SWIFT_VERSION = 6.0`). Do not reintroduce Swift 5 mode or weaken the
concurrency checks.

## Knowledge Bundles (OKF)

Both projects ship their own Open Knowledge Format v0.2 bundle: plain markdown with
YAML frontmatter that gives humans and AI agents a navigable reference to that
project. They stay independent like the projects themselves — neither bundle
imports or describes the other's sources.

| Project | Bundle | Regenerate | Drift gate |
| --- | --- | --- | --- |
| `ios/` | `ios/knowledge/` | `swift run VoltLinkCLI okf export` | `swift test` (`KnowledgeBundleTests`) |
| `android/` | `android/knowledge/` | `./gradlew testDebugUnitTest --tests '*KnowledgeBundleTest' -Pokf.export=true` | `./gradlew testDebugUnitTest` |

In both bundles `architecture/` is hand-authored and `vehicles/`, `telemetry/`,
`diagnostics/`, and every `index.md` are generated.

- **iOS sources:** `VehicleProfileID`, any vehicle profile's commands or
  `supportedMetrics`, `Core/Telemetry/TelemetryMetric.swift`, and
  `Data/Seed/dtc_definitions.json`.
- **Android sources:** `VehicleProfileId`, any profile's commands or
  `supportedMetrics`, `core/telemetry/TelemetryMetric.kt`,
  `app/src/main/assets/dtc_definitions.json`, and
  `app/src/main/assets/vehicle_catalog.json`.
- Update the relevant `<bundle>/architecture/*.md` concept in the project you changed
  when the data flow, concurrency rules, charging/trip behavior, demo mode, or test
  commands change. New architecture docs are indexed automatically by the next
  export.
- Both gates fail the normal test command, so regenerate before running the suite.
  Never hand-edit generated concepts or `index.md`.
- Keep frontmatter `type`, `title`, and a one-line `description` on every
  hand-authored concept; they drive the generated indexes.
- Hand-authored concepts are never rewritten by an export, but the indexes are:
  adding a link to a new architecture page needs an export, not an index edit.

## Architecture

Keep the data flow one-way: BLE adapter -> parser -> vehicle profile ->
manager -> SwiftUI/CarPlay view.

- `Core/Bluetooth/BluetoothManager`: CoreBluetooth / ELM327 connection.
- `Core/OBD/ISO15765Parser`: ISO-TP frame reassembly.
- `Core/Vehicles/`: `VehicleProfile` implementations, polling commands, and
  response decoding.
- `Core/Demo/MockOBDAdapter`: simulation-backed implementation of the
  connection protocol.
- `Services/VehicleDataManager`: main-actor telemetry facade; publishes an
  `@Observable` snapshot plus a `telemetryPublisher` for non-UI consumers.
- `Services/TelemetryPollingLoop`: cancellable async polling loop.
- `Core/Telemetry/`: plausibility bounds, SoC-slope charging estimator, and SOC
  reference persistence used by the manager.
- `Services/DTCScannerService`: DTC scanning and clearing.
- `Services/TripTrackingManager` and `Core/Location/TripLocationManager`:
  trip recording and location authorization.
- `Core/Units/UnitPreferences`: display-unit conversion (km/mi, °C/°F,
  kW/hp). Telemetry stays SI; exports always use SI.
- `Core/Notifications/NotificationService`: opt-in local alerts (charging
  finished, adapter lost mid-trip, fault codes).
- `Core/Sharing/`: app-group telemetry snapshot and Live Activity attributes
  shared with the widget extension.
- `Services/AppIntents`: Siri/Shortcuts actions for charge status and trip
  control.
- `App/AppEnvironment`: shared observable-object composition root.
- `CarPlay/`: CarPlay scene/dashboard.
- `Widgets/`: WidgetKit extension (Home Screen widget + Live Activity). Only
  `Core/Sharing` compiles into both the app and the extension; widget sources
  stay out of the app target so their `@main` bundle does not conflict.
- `Data/Models/`: SwiftData models; register new models in the current
  versioned schema (`VoltLinkSchemaV2` via `VoltLinkCurrentSchema`). Additive
  changes use inferred lightweight migration; destructive changes need distinct
  legacy model copies plus a migration stage.
- `UI/DesignSystem/Theme.swift`: shared colors and UI tokens.

## Implementation Rules

- Keep iOS-only APIs behind `#if canImport(CarPlay)` or `#if os(iOS)` so SPM
  tests continue to compile on macOS.
- Swift 6 concurrency is enforced, not aspirational: protocol-conforming
  vehicle/connection types must remain `Sendable`; `OBDConnectionProtocol`,
  `OBDConnectionDelegate`, and the managers are `@MainActor`, and `sendCommand`
  completions are `@MainActor @Sendable`.
- Parse multi-line ELM327 CAN responses through `ISO15765Parser`, not directly
  from raw adapter text. The EQA uses UDS Service `0x22` on CAN IDs `7E4` and
  `7E0`.
- Use `Theme.swift` tokens instead of hard-coded colors. Follow native Apple
  HIG and the existing glass/material styling.
- Background location updates require confirmed `.authorizedAlways` status;
  do not enable or request them proactively.
- Widget data crosses targets only through the
  `group.com.simonkaring.voltlink` app group (`SharedTelemetryStore`); never
  add SwiftData or CoreBluetooth code to the extension.
- Request notification permission only from a user action (enabling the
  Settings toggle), never at launch.

## Change Discipline

- Prefer the smallest change that follows existing project patterns. Avoid new
  dependencies and speculative abstractions.
- Preserve demo mode and generic OBD-II support when changing vehicle-specific
  behavior.
- Use Conventional Commits when committing:

  ```text
  type(scope): imperative summary

  Detailed explanation of the change, root cause, and affected modules.
  ```

  Valid types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`,
  `chore`, `ci`. Typical scopes: `telemetry`, `obd`, `bluetooth`, `carplay`,
  `ui`, `location`, `diagnostics`, `models`, `xcodeproj`, `deps`.
