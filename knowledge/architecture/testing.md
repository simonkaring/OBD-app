# Commands

```bash
swift test                                                                    # engine + UI logic on macOS
xcodebuild -scheme VoltLink -destination 'platform=iOS Simulator,name=iPhone 17' build
xcodebuild test -scheme VoltLink \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -only-testing:VoltLinkUITests                                               # demo-mode smoke test
swift run VoltLinkCLI okf export                                              # regenerate knowledge/
swift run VoltLinkCLI okf check                                               # validate knowledge/
swift format lint --strict --recursive --configuration .swift-format \
  Package.swift App CarPlay Core Data Services UI Widgets Tests UITests Tools        # formatting gate
```

Run `swift test` after changing PID decoders, ISO-TP parsing, SwiftData models,
charging/trip tracking, or the knowledge bundle. Build the Xcode scheme for
iOS-only code (`UI`, `CarPlay`, `App`).

# Conventions

- Use `XCTest`. Every test class is `@MainActor`; the managers and adapter
  contracts are main-actor isolated.
- Inject a scripted `OBDConnectionProtocol` double (`CalibrationMockAdapter`,
  `ScriptedConnection`) instead of the real `BluetoothManager`.
- Prefer timestamped `applyUpdates(...)` calls over sleeps to make time-based
  behavior deterministic.
- `telemetryPublisher` is a `PassthroughSubject`; do not add `.dropFirst()` to
  subscriptions that expect the first applied snapshot.
- Assert on absence (`hasChargePower == false`) rather than on zero-valued
  sentinels when a value is unknown.
- When a test reproduces a bug, keep it: the suite encodes behavior contracts.

# Widget extension

The widget/Live Activity target is built by the Xcode scheme, not by
`swift test`; widget sources are excluded from `VoltLinkEngine` so their
`@main` bundle cannot conflict with the app. Live Activity updates and app-group
sharing therefore need a manual simulator run (or the UI test scheme build) to
verify. App-group data sharing requires the group to be provisioned for signed
builds.

# Verification gates

There is no hosted CI today, so these gates are run locally and their results
belong in the change description: `swift test`,
`swift run VoltLinkCLI okf check`, and the swift-format lint, followed by an
Xcode build of the regenerated project and the UI smoke test on a simulator.
The Xcode project is generated by `scratch/make_xcodeproj.py`; regenerate it
after adding files or targets.

# Knowledge bundle drift

`KnowledgeBundleTests` compares `knowledge/` with `KnowledgeBundle.conceptFiles()`
and `KnowledgeBundle.indexFiles(in:)`. Any change to `VehicleProfileID`,
`TelemetryMetric`, profile commands, or `Data/Seed/dtc_definitions.json` without
re-running `okf export` fails `swift test`. Hand-authored
[architecture](/architecture/data-flow.md) concepts are indexed automatically;
add or edit them directly.
